# ADR-010: 承認経路は、候補が1つなら自動、複数ならカードで本人が選ぶ

- **Status:** Accepted
- **Date:** 2026-09-29

---

## Context

有給申請や残業申請では、承認経路(`approval_flow_route_id`)の指定が必須である。部署ごとに経路が違うこともある。
経路によって承認者が決まるので、誤って選ぶと別の人に申請が届いてしまう。

---

## Decision

- 勤怠申請(`usage=AttendanceWorkflow`)に使える経路の一覧を取得する
- 候補が1つなら自動で選ぶ
- 複数あるときは確認カードのセレクトボックスで本人が選ぶ。前回使った経路を覚えておき、初期値にする
- **LLM には選ばせず、ユーザーに聞くこともさせない**
- 経路を選ばないまま「申請する」を押したら、止めて選択を促す

---

## Rationale

承認者に関わる選択なので、人が明示的に選ぶべき。前回の経路を覚えておけば、2回目からはほぼ手間がかからない。

---

## Options Compared

| Option | Pros | Cons |
|---|---|---|
| **1つなら自動、複数ならカードで選択+前回を記憶** (selected) | 安全で、手間も少ない | 初回は選ぶ必要がある |
| 申請の種類ごとに設定ファイルで固定 | 何も選ばなくてよい | 部署ごとに違う経路に対応できない |
| LLM が会話の中で選ぶ | 会話だけで済む | 誤って選ぶ危険がある |

---

## Trade-offs

**Pros:**
- 承認者を誤るのを防げる

**Cons / Constraints:**
- 部門や役職の連携を使っている経路は、API から申請を作れない(freee API の制約)

---

## Impact

`service._routes`、`user_preferences`、確認カードの `route_select`。
